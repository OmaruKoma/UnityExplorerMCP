Runtime MCP · not Editor MCP

Give your agent a grip on a running Unity game.

UnityExplorerMCP puts a Model Context Protocol server in front of the live game process. Walk the scene, explore the type system, read and write fields, call methods, execute C# in-process and tail the BepInEx log — over IL2CPP and Mono, from any MCP client.

Download Install guide Source on GitHub

What it looks like

One prompt, a chain of tool calls, a live answer — no Editor, no rebuild, no restart loop.

> "The shop button does nothing. Find the shop controller, work out what it
  expects, and call it the way the UI would."

unity_capabilities          {}                                  → backend, session, limits
unity_find_objects_of_type  { "type": "Game.ShopController" }    → handles
unity_inspect               { "handle": "ShopController#7:-33814" }
unity_search_members        { "name_contains": "Open" }
unity_get_field             { "handle": "ShopController#7:-33814", "field": "_isReady" }
unity_invoke_method         { "handle": "ShopController#7:-33814", "method": "Open" }
unity_tail_log              { "lines": 50 }                      → what happened next

Features

Built for agents: bounded outputs, explicit limits, honest capability reporting.

01

Live runtime inspection

GameObjects, components, fields, properties and methods of the actual running process.

02

Reflection, everywhere

Type discovery and member search across every loaded assembly, plus live instance lookup.

03

Read, write, call

Instance and static fields/properties, method invocation including out/ref.

04

C# in the game

Self-hosted Mono.CSharp engine — no UI dependency, same flavour as UnityExplorer's console.

05

Session-aware handles

session:id handles; stale ones fail fast with STALE_HANDLE instead of hitting a wrong object.

06

Agent-sized output

Pagination, truncation with sha256, bounded member lists and structured errors.

07

Harmony inventory

Read-only list of patched methods and their patch owners.

08

Log tailing

Read BepInEx/LogOutput.log without locking the game — works while the game is closed.

09

IL2CPP + Mono

One tool surface across BepInEx 5 and 6, IL2CPP and Mono backends.

Install

You need a Unity game with BepInEx, Node.js 18+ for the server, and .NET SDK only if you build the bridge yourself.

Drop the bridge into the game

Download the zip matching your loader and extract it into <GAME_ROOT>/BepInEx/plugins/. The DLL and mcs.dll must stay side by side.

UnityExplorerMCP-<version>-IL2CPP.zip          # BepInEx 6 + IL2CPP
UnityExplorerMCP-<version>-Mono-BepInEx6.zip   # BepInEx 6 + Mono
UnityExplorerMCP-<version>-Mono-BepInEx5.zip   # BepInEx 5 + Mono

Start the server

unzip unity-explorer-mcp-server-<version>.zip
cd unity-explorer-mcp-server-<version>
npm ci --omit=dev
node dist/server.js        # speaks MCP on stdio

Point your client at it

{
  "mcpServers": {
    "unity": {
      "command": "node",
      "args": ["<REPO_PATH>/mcp-server/dist/server.js"],
      "env": { "UNITY_BRIDGE_URL": "http://127.0.0.1:12345" }
    }
  }
}

Verify the chain

Ask your agent to call unity_capabilities. If it answers, the bridge, server and client are all live.

Safety

The bridge listens on 127.0.0.1 only and executes arbitrary C# sent by the agent. Treat it like an attached debugger: run it against games you own, on your own machine. set_* and invoke_* mutate live runtime state — inspect first.
